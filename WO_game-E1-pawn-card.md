(ось игрового слоя 4A). Исполнитель: Claude Code, Windows 11, PowerShell. Отдельной веткой.

> «Одна великолепная карточка с полной личной хроникой»: журнал ОДИН, карточки — ПРЕДСТАВЛЕНИЯ.
> Строим не новый сбор данных, а проекции по oid поверх существующего EventLog. Мост лаборатория→мир:
> не графики Gini, а НАРРАТИВ пешки («потеряла дом → должник дома X → предала делегировавшего»).

## 0. Что уже есть (фундамент — факт из кода, не глосса)

- **`Code/sim_eventlog.py`** — единый журнал `Event(t,kind,scale,where,actor,parent,dm,data)` + готовые
  `lineage(oid)`, `descendants(oid)`, `perspective(oid)` (эгоцентричный срез «что ЭТА пешка могла знать»),
  `narrate(events)` (проза для LLM), `query(...)`. Детерминизм + **faithfulness-аудит**: лог реконструирует
  живую популяцию точно на каждом чекпоинте (`reconstruct_live`). Канон, не трогаем.
- **Словарь событий Polis** (verbatim из `viz_export.py`, гейт V-complete): `birth/death/seed/move` ·
  `artifact_write/copy/read/store/capital/store_draw/capital_boost/ruin` · G2 `extort`/`delegate_remit` ·
  `cognition/communication/forget`. `dm` = поток массы события (→ PowerFlow); `data` = структурная нагрузка.
- **`stage3/viz_export.py`** — паттерн чистого ридера: гейт **V-OFF** (fp прогона == чистого ⇒ ридер не
  мутировал мир), `_Houses(events)` реконструирует `house(oid)` из лога, детерминированный пакет
  (sorted keys, SHA-якорь). Снимки уже несут per-oid: `pawns[oid,i,j,body,house,phase]`, `known`-рёбра
  Данбара, `owners`, `marks/guard/deny`, `delegate_root`/`guard_ids`.
- **viz-стек**: FastAPI (`viz/server.py`) над `.jsonl`, `static/` canvas-фронт; β-3 «Власть глазами»
  (`viz/glass/`) — слои власти над Polis. E1 — продолжение 4A, «сцена и данные готовы» (viz roadmap).

**Вывод:** E1 не добавляет ни строки в канон/polis.py. Это НОВЫЙ ридер-модуль + фронт поверх того же лога.

## 2. Шесть проекций (каждая — чистый фолд/запрос по oid поверх журнала)

Все — read-only функции над `EventLog` (+ снимки, где нужно пространство-время). Ни одна не трогает мир.

| карточка-представление | источник в журнале (по oid) | форма |
|---|---|---|
| **PawnChronicle** | `lineage(oid)` + `perspective(oid)` + собственные birth/death | хроника жизни линии (готово в каноне — рендерим) |
| **RelationshipHistory** | `known`-рёбра Данбара по тикам (oid как узел) + `communication` + `extort`/`delegate_remit`, где oid — актор ИЛИ цель (в `data`) | граф/таймлайн связей: кого знал, кого вымогал, кому ремитил |
| **PropertyHistory** | `owners` из снимков ∩ oid по тикам + claim/appropriate/inherit/trade/exclude-события, касающиеся oid | таймлайн владения клетками: приобрёл→держал→потерял/завещал |
| **HouseHistory** | `_Houses.house(oid)` + основатель линии + inherit-события (oid как наследодатель/наследник) | родовая принадлежность, глубина поколений, преемственность |
| **PowerFlowHistory** | `dm`-несущие события к/от oid: `extort` (изъято у oid / oid-стражем), `delegate_remit` (oid→root), налог, аппроприация; + статусы guard/branded/root | леджер потоков массы-власти per oid |
| **ReputationHistory** | репутационные сигналы на oid: extort-reputation клейма, `_delegate_marks` (branded), gossip/trust-события | траектория репутации/клейма во времени |

**Пробел, закрываемый в Ф0:** точные `data`-ключи для claim/inherit/trade/reputation в текущем коде не
все перечислены в экспортёре (он рендерит подмножество). Ф0 — форензика per-oid следа: какие `kind`+`data`
несут oid как актора/родителя/цель/владельца/наследника/root/branded. Манифест «событие→карточка», гейт
**E1-MAP-COMPLETE** (каждый per-oid-релевантный `kind` отнесён к карточке или явно IGNORED — по образцу
RENDERED/IGNORED в `viz_export`).

## 3. Ассемблер + нарратив (ядро «великолепной карточки»)

- **`pawn_card(events, snapshots, oid) -> dict`** — собирает шесть проекций в один объект. Детерминирован,
  sorted-keys, SHA-якорь (как glass-пакет).
- **Нарратив (Ф2)** — проза поверх шести проекций, LLM-ready, по образцу `log.narrate`: связная личная
  хроника, а не таблица. Цель-образец (viz roadmap E2): «потеряла дом → должник дома X → предала
  делегировавшего». Это и есть мост лаборатория→мир. Опора — `perspective`+`narrate` уже в каноне.

## 4. Фронт (Ф3) — представление карточки

Карточка — ПРЕДСТАВЛЕНИЕ поверх пакета проекций. Два пути (решение Стана §7):
- **(A) эндпоинт в viz-сервере** `/pawn/{oid}` + карточное представление в `static/`, поверх glass-пакета
  (переиспользует существующий бэк/скраб; клик по пешке в Glass Polis → её карточка). Интегрировано.
- **(B) самодостаточный HTML-артефакт карточки** (инлайн CSS/JS, один oid, экспортируется как файл) —
  автономно, шарится, но вне glass-UI.

Рекомендация: **A как основа** (карточка живёт в том же аквариуме, что β-3 — естественный клик-in),
**B как экспорт-режим** флагманской карточки (для книги/шаринга). Оба — читатели, канон нетронут.

## 5. Гейты (зелёные до/после; приёмка по отпечаткам)

- **E1-VOFF** — fp прогона-под-ридером == чистого прогона (ридер не мутировал мир). Аналог V-OFF glass.
- **E1-DET** — та же CLI/сид → байт-идентичный пакет карточки (SHA-якорь; sorted keys, compact).
- **E1-FAITHFUL** (ядро) — PropertyHistory, реконструированная из ЛОГА одного, совпадает со снимковым
  `owners` для oid на каждом тике (принцип `reconstruct_live` из `sim_eventlog`: лог — не lossy). Если
  расходится — карточка врёт про владение, СТОП.
- **E1-MAP-COMPLETE** — каждый per-oid-релевантный `kind` отнесён к карточке или IGNORED (§2 Ф0).
- **MK-CANON** — `Code/` И `stage3/polis.py` байт-в-байт; `verify_all` ALL PASS.

## 7. Решения Стана (нужны ДО Ф1)

1. **Фронт** — A (эндпоинт в glass-UI) / B (автономный HTML) / оба? (рекомендация: A основа + B экспорт).
2. **Фокальная пешка** — кого героем флагманской карточки: самая длинная линия (`lineage`), павший
   владелец (потерял клетки), делегат-дефектор (branded→revoke)? (рекомендация: тот, чья история задевает
   максимум карточек — павший владелец из наследного дома под G2).
3. **Объём витка** — все шесть проекций сразу, или сперва трио «уже-поддержано» (Chronicle+Property+House),
   а Relationship/PowerFlow/Reputation вторым заходом? (рекомендация: трио → нарратив → фронт как виток 1,
   остальные три — виток 2; чтобы флагман встал быстрее).
4. **Конфиг-сцена** — showcase дефолт (arena 6, Demerzel-имплант) или включить G2 (`--extort/--delegate`),
   чтобы PowerFlow/Reputation вообще имели что показать? (рекомендация: G2-ON сцена — иначе три карточки пусты).
