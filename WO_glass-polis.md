## 1. Что строим

Два артефакта:

**A. Экспортёр** `stage3/viz_export.py` — прогоняет полис в «шоукейс»-конфиге и пишет
пакет данных `viz/glass/data/` (jsonl + json). Питон stdlib + numpy (уже есть).
Никаких новых зависимостей.

**B. Рендерер** `viz/glass/index.html` — ОДИН самодостаточный файл: vanilla JS +
canvas, **ноль внешних зависимостей, ноль CDN, ноль сборки** (файл открывается
двойным кликом оффлайн — он же потом поедет на Raspberry Pi как «аквариум»).
Загрузка данных: `fetch('./data/…')` при запуске с локального сервера
(`py -m http.server`) ИЛИ drag&drop файлов в окно (обязательно поддержать оба пути,
т.к. `file://` блокирует fetch).

## 3. Формат данных (контракт экспортёр ↔ рендерер)

`viz/glass/data/meta.json` — один объект:
```json
{ "schema": "glass-1", "seed": 7, "days": 400, "arena_side": 6,
  "cfg": { …полный конфиг… }, "M0": <float, инвариант на t=0>,
  "houses": [<house ids>], "snapshot_every": 1,
  "event_types_rendered": […], "event_types_ignored": […] }
```

`snapshots.jsonl` — по строке на снапшот, каждые `--every` тиков (дефолт 1):
```json
{ "t": 17,
  "pawns": [[oid, i, j, body, house, phase], …],
  "arts":  [[aid, kind, i, j, mass, salience, maker_oid], …],
  "owners": [[i, j, oid], …],
  "soil":  [<row-major, round(v,2)>…],        // полный грид каждые 10 тиков,
  "plant": [<row-major, round(v,2)>…],        // между ними поля опущены
  "known": [[oid_a, oid_b, w], …],            // см. эвристику Э-3
  "metrics": { "pop": n, "gini_body": g, "mass_vessel": x, "mass_store": y,
               "mass_capital": z, "invariant": s } }
```

`events.jsonl` — по строке на событие: `{"t":…, "type":…, "actor":…, "where":[i,j],
"dm":…, "data":{…}}` — прямой прокси лога, БЕЗ переименований типов.

**Правило полноты:** экспортёр обязан перечислить в `meta.json` КАЖДЫЙ тип события,
встреченный в логе, ровно в одном из двух списков — `rendered` или `ignored`
(гейт V-complete). Фактические имена типов НЕ выдумывать — извлечь из кода:
`Code/sim_eventlog.py` (канонические: рождения/смерти/дань/克…), `stage3/polis.py`
(шёпоты/директивы/know/unknow), `stage3/artifact.py` (`artifact_write`, `artifact_read`,
`artifact_copy`, `artifact_ruins`, `artifact_store`, `artifact_capital`,
`artifact_store_draw`, `artifact_capital_boost` — сверить по grep `log.emit`).

**Бюджет пакета: ≤ 15 МБ** на 400 тиков box6. Рычаги: `--every`, квантование float
(2 знака хватает для рендера; метрики и invariant — 6 знаков), поля soil/plant раз в
10 тиков, эвристика Э-3 по known-рёбрам. Если не влезает — сначала рычаги, потом
торг за схему.

## 4. Рендерер: слои и интеракции

Канва: грид arena_side×arena_side, клетка ~96px на десктопе, ресайз по окну.
Справа — панель (метрики, хроника, инспектор), снизу — таймлайн.

**Слои (чекбоксы, все ON по умолчанию), от земли к смыслу:**

1. **Земля.** Heatmap soil (тёмная гамма) + plant (зелёная). Между полными гридами —
   линейная интерполяция по t (Э-6).
2. **Тела.** Круг: радиус ∝ sqrt(body) (клампы Э-2), заливка = цвет дома (Э-1),
   обводка = фаза арки (юность/зрелость/старость — маппинг фаз взять из `pawn.py`
   по факту). Рождение — расцветание за ~300мс, смерть — угасание в серый + крестик
   на 2 тика.
3. **Собственность.** Рамка клетки цветом владельца (полупрозрачно). Событие дани —
   короткий пульс-искра от едока к владельцу.
4. **Артефакты.** Глифы по kind: vessel — стела ▮, store — амбар ⌂, capital — шестерня ⚙
   (рисовать canvas-путями, не emoji — детерминизм рендера на разных ОС).
   **Размер глифа ∝ mass, свечение-гало ∝ salience — раздельно.** Это центральный
   визуальный тезис: предмет, который ещё стоит, но уже погас (mass>0, salience≈0),
   обязан читаться с одного взгляда как «нечитаемая руина». `artifact_read` — искра
   у глифа; `artifact_copy` — дуга от оригинала к копии; `artifact_store_draw` —
   капля амбар→тело; `artifact_capital_boost` — пульс из клетки сквозь шестерню в
   тело; `artifact_ruins` — глиф рассыпается в точки, впитывающиеся в землю.
5. **Данбар.** Полупрозрачные рёбра known между пешками, alpha ∝ w; `unknow` —
   ребро рвётся (короткая красная вспышка). Слой OFF по умолчанию при pop>120 (Э-3).
6. **Голос бога.** Демерзель — отдельный глиф (око) в углу клетки присутствия; аура
   цветом директивы (PROMOTE — золото, DISCORD — красный, IMPLANT — фиолет; сверить
   фактический словарь директив по `directive.py`). Шёпот — расходящаяся волна;
   каскад повторов — тонкие стрелки между пешками.
7. **Лента метрик.** Спарклайны pop / gini_body / mass по kind. Отдельной строкой —
   **инвариант**: `|Σ − M0|`, зелёная плашка пока < 1e-9. Инвариант — персонаж.

**Интеракции:** play/pause/шаг/скорость (0.5–16×); скраббер с мини-графиком pop;
клик по пешке — инспектор (oid, дом, body-спарклайн, счётчик know, что написала/
прочитала); клик по артефакту (aid, kind, mass/salience-спарклайны, maker, история
читателей); хроника событий текущего тика с фильтром по типам, клик → подсветка
локуса; кнопка «кадр в PNG» (`canvas.toBlob`); hotkeys: space, ←/→, 1–7 слои.

## 5. Эвристики (вкусовые решения — принять и ЗАДОКУМЕНТИРОВАТЬ в шапке index.html)

- **Э-1 Палитра домов:** детерминированная от house id: `hue = (id * 137.508) % 360`
  (золотой угол), s/l фиксированы. Никаких random-палитр.
- **Э-2 Масштабы:** радиус тела `r = clamp(4 + 10*sqrt(body/REPRO), 4, 26)px`;
  свечение salience — γ-кривая (γ≈0.6), чтобы затухание читалось в верхней зоне.
  Подписать константы, дать «крутилки» в debug-панели (query `?debug=1`).
- **Э-3 Данбар-рёбра:** в снапшот класть на пешку максимум top-8 known по весу; если
  рёбер в кадре > 600 — рендерить только внутрикластерные (кластер = клетка+соседи).
  Полный реестр в данные не тащить.
- **Э-4 Плотность событий:** если событий одного типа в тике на клетке > 5 —
  агрегировать в один глиф со счётчиком («×23»), не рисовать 23 искры.
  `artifact_capital_boost` при open-доступе — тысячи событий: агрегировать ВСЕГДА
  до пульса-в-тик с суммарным dm.
- **Э-5 Коллизии на клетке:** несколько пешек — раскладывать по спирали Фибоначчи
  внутри клетки (детерминированно от oid); артефакты — в углах клетки по kind
  (vessel NW, store NE, capital SW), Демерзель SE.
- **Э-6 Интерполяция:** позиции пешек лерпить ТОЛЬКО при |Δi|+|Δj| == 1; скачок
  дальше — телепорт без лерпа (смерть+рождение oid-реюза не путать с движением —
  сверять по событиям birth/death). Между редкими snapshot'ами полей — линейная
  интерполяция; событийные вспышки привязывать к дробному t.
- **Э-7 Производительность:** три canvas-слоя (земля / стабильные глифы / вспышки),
  перерисовка земли только на смене снапшота; requestAnimationFrame; цель — 60fps
  на box6/побольше и «не хуже 20fps» на Pi 5 (проверять не нужно, но не делать
  ничего заведомо тяжёлого: без теней blur>8px на сотнях объектов, без re-layout DOM
  в кадре).

Каждую эвристику пометить в коде комментарием `// Э-N:` — они кандидаты на пересмотр.

## 6. Гейты V-* (новый файл `stage3/run_glass_v.py`, тот же стиль, что run_artifact_f2)

- **V-OFF** — экспорт не возмущает мир: `state_fingerprint()` прогона С экспортом ==
  fingerprint того же конфига БЕЗ экспорта (экспортёр обязан быть чистым читателем).
- **V-replay** — два запуска экспортёра с одними аргументами → SHA-256 всех файлов
  пакета бит-в-бит (печатать SHA пакета — это якорь-кандидат).
- **V-invariant** — в КАЖДОМ снапшоте `|metrics.invariant − M0| < 1e-9`.
- **V-complete** — множество типов из `events.jsonl` == `rendered ∪ ignored` из meta,
  пересечение rendered ∩ ignored пусто.
- **V-schema** — валидатор структуры (stdlib, без jsonschema-зависимости): типы полей,
  границы координат, kind ∈ {vessel,store,capital}, монотонность t.
- Плюс полная регрессия `--all` из п.0.2.

Рендер-детерминизм JS в CI не гоняем — фиксируется правилом «ни одного Math.random()
и ни одной зависимости от wall-clock в отрисовке состояния» (время — только параметр
анимационных вспышек); проверить grep'ом перед коммитом.
