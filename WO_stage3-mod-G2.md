## Фаза 1 — EXTORT: нелегитимный перенос (заход 1)

**Механика** (всё на готовой инфраструктуре дани 23):
- Верб `EXTORT` в реестре интента (строка в таблице). Физика — сохраняющий перенос
  тело→тело, **обратный знак дани**: не-владелец (вымогатель), со-присутствуя на клетке,
  забирает долю у владельца. Ставка `rho_extort` — отдельный параметр, дефолт = `rho`
  (зеркало легитимной дани; см. §Решения).
- **Гейт нелегитимности:** EXTORT срабатывает ТОЛЬКО когда страж-24 НЕ со-локализован
  (по определению из VERIFY #3) — преступность живёт в тени присутствия.
- Всё под интент-слоем: EXTORT проходит `approve()`; все четыре политики его видят;
  деny-источники размечаются как в витке 1. Флаг выключен ⇒ верб не существует.
- Память исходов получает локусы (кто/где) — инфраструктура для смычки с репутацией
  и для будущего DELEGATE.

**Гейты MG2-*** (раннер + прогон, все обязательны):
- `MG2-OFF` — extort выключен по дефолту ⇒ **все четыре** якоря байт-в-байт;
- `MG2-mass` — drift < 1e-9 на каждой конфигурации (перенос сохраняющий по построению);
- `MG2-illegit` — при со-локализованном страже EXTORT не срабатывает; мир прогона
  «страж вездесущ» ≡ миру без верба (fingerprint равен);
- `MG2-replay` — live via-log бит-в-бит без ключа;
- verify_all — ALL MODULES PASS перед PR. Красное не мержить.

**Пре-рег HG2-*** (честные базы с ПЕРВОГО прогона: интегралы за жизнь, исторические
множества, base rates, корона-на-кладбище; демография — исход, не фон):
- **HG2-1:** строит ли страту нелегитимный захват? (концентрация по телам с extort vs
  без, обе арены). Да → легитимность вторична для физики присвоения. NULL → присвоение
  безразлично к основанию права — острый тезис для книги.
- **HG2-2:** цена нелегитимности. Страж давит extort сильнее или слабее, чем давил
  легитимный вызов (база из VERIFY #3)? Разница = измеримая цена нелегитимности.
- **HG2-3** (если VERIFY #2 дал механику): метка вымогателя → снижение будущего
  доступа → самоограничение. Зеркальность к ВСТАВКЕ-29: обе стороны «источника права»
  на одной механике.

## Фаза 2 — DELEGATE / REVOKE: михельсова дыра (заход 2, после отмашки)

**Механика:**
- Дань C→B — существующий сохраняющий шов; **мета-дань B→A** — доля `m` от собранного,
  тело→тело. «Право делегирования» — леджер-отношение, permission-only, mass-neutral,
  в blob — kind-суффиксом. Корень A физически отсутствует на клетке делегата — в этом
  весь смысл: k делегатов = k клеток разом, институциональный обход потолка присутствия.
- **Свип зуба отзыва (обязателен, REVOKE без зуба бессилен):**

| зуб | механизм | пре-рег предикт |
|---|---|---|
| (a) нет | делегат может игнорить (defect-флаг) | delegate ≡ распределённое владение; дельта РАВНА мод-23 |
| (b) репутация | дефектный делегат метится, теряет доступ | мягко, вряд ли пробьёт потолок |
| (c) энфорсер | отзыв исполняет страж-24 | «черепахи вниз»: потолок переезжает на уровень стража |
| (d) авто | леджер сам откатывает (god-physics) | ⛔ чит — только контрольная граница, НЕ рабочий режим |

**Метрика (owner_gap слеп by design — новая ось):** доля потока через держателя
права-отзыва vs его собственное ТЕЛО; ключевой профиль — телесно-бедный+потоко-богатый
корень; глубина/ширина цепи. Знаменатель — реальный класс `owner_ids()`, не узкий
`_owner_ids` (урок mod F: кого кладёшь в знаменатель — решает результат).

**Контроль:** DELEGATE при ВЫКЛЮЧЕННОМ наследовании; concentration-дельту сравнивать с
уже-измеренной дельтой `_house` (25) — чистый контраст «династия vs бюрократия».

**Фальсифицируемые исходы:** профиль присвоения без пробоя → зуб необходим, аппарат без
энфорсмента пуст; пробой только при (d) → без субстратного чита фазового перехода нет;
пробой при (b)/(c) → найдена вторая проводимость власти. Все исходы информативны.

**Гейты:** `MG2D-OFF` (все якоря + якорь EXTORT-мира), `MG2D-mass`, `MG2D-replay`,
`MG2D-teeth` (зуб (d) откатывает всё → контроль честности леджера). verify_all перед PR.
