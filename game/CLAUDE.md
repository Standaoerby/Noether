# game/CLAUDE.md — закон подкаталога game/

Ты работаешь в игровом клиенте Noether (Godot 4, .NET-сборка). Прочти
`docs/game-architecture.md` (КОНТРАКТ) и `docs/game-vision.md` (компас)
до первой строки кода. Правила этого файла дополняют корневой CLAUDE.md.

## Нерушимое

1. Клиент НИКОГДА не считает игровую логику. Ядро (Python) — источник
   истины; клиент рендерит снапшоты и шлёт команды. Если хочется «немного
   посчитать на клиенте» — это ошибка дизайна, остановись и спроси.
2. Протокол = `docs/game-architecture.md`. Любое изменение сообщений —
   сначала правка контракта в том же PR, `protocol_version` по правилам.
   Незнакомые поля игнорируй, свои необязательные — добавляй смело (минор).
3. Никакой клиентской случайности в командах. Косметический RNG живёт
   только в презентации и пересевается от tick на границе фазы.
4. `Code/sim_*.py` не трогать никогда. `stage3/gameserver.py` — тонкая
   обёртка: применение команд на границе тика + сериализация; логика мира
   в него не просачивается.

## Стиль Godot

- Старт на GDScript; статическая типизация везде (`var x: int`), сцены
  плоские и маленькие, один скрипт — одна ответственность.
- UI — Control-ноды (не рисуй UI руками в _draw без причины).
- Горячие пути (парсинг снапшотов тысяч агентов) — кандидаты на C#;
  не переписывай на C# превентивно, только по замеру.
- Godot API проверяй по документации 4.x — не выдумывай методы; при
  сомнении в сигнатуре найди в docs, это дешевле отладки галлюцинации.

## Quality-gate (сверх юнит-тестов)

Тесты зелёные ≠ игра работает. Перед PR обязательный ручной смоук:
подключение → 10 минут на 20x → пауза/резюм → клик по агенту. Скриншот
каждого нового UI-элемента — в отчёт. «Запускается и наглядно» — критерий,
а не «компилируется».

## Дисциплина репо (та же, что везде)

Один PR на WO; красное не мержить; WO закоммитить с работой; docs после
мержа — только с main; стоп-точки соблюдать; маркеры свежести проверять.
Гейты GAME-OFF / GAME-DET / GAME-PROTO — святые: башня не должна ощущать
существование игры.
