## Багфикс (14.07, после диагностики Гайки)

Симптом: Godot-клиент разрывал соединение сразу после handshake; сервер
(одиночный accept) после отвала завершался совсем. Python-смоук проходил →
причина в Godot-специфике.

- **FIX-3 (корень):** `Net.gd` был написан под старую семантику. В Godot 4.4+
  `StreamPeerTCP` транзиентно отдаёт `STATUS_NONE` сразу после приёма данных
  (godotengine/godot#62001), хотя связь жива. Старый код фейлился на ПЕРВОМ же
  `NONE` — т.е. на кадре после чтения серверного `hello`. Теперь клиент терпит
  транзиентный `NONE` (грейс-счётчик, сброс при `CONNECTED`/приходе данных),
  всегда сначала вычитывает буфер, и падает только по `STATUS_ERROR` или
  устойчивому `NONE`. Семантика `poll()`/`get_status()`/`get_partial_data`
  сверена с docs текущей stable, не с памятью.
- **FIX-1:** `gameserver.py` — accept в цикле: после отвала клиента сервер
  возвращается слушать (лог `client gone, listening again`), та же сессия
  (мир/тик/`commands.jsonl`) продолжается при реконнекте; Ctrl+C — чистый выход
  (accept с таймаутом, чтобы KeyboardInterrupt проходил на Windows).
- **FIX-2:** серверная диагностика — причина завершения `_drain_socket`
  (пустой read / reset+errno), лог принятых `pace`/`ping`, `first snapshot:
  tick N -> M agents`, флаг `--verbose` для полного трафика.

**Проверка фикса:** Godot 4.7 headless против сервера — клиент держит связь весь
прогон, **18 снапшотов tick 1→18** за 9 c без единого обрыва (раньше падал на
tick 1); ноль runtime-ошибок. Реконнект (Python): клиент B входит в ту же
сессию `reconn`, непрерывность тика сохранена; сервер разлогировал clean-close
vs reset(10054).

## Что сделано

**Серверный слой — `stage3/gameserver.py`** (тонкая обёртка, канон не тронут):

- TCP loopback `127.0.0.1:42017`, line-delimited JSON (§1.1).
- Handshake: клиентское `hello` с `protocol_version`; несовпадение мажора →
  `error/protocol_mismatch` + закрытие, не тихий сбой. Сервер отвечает
  `hello{core_commit, seed, session}`.
- Темп-контроль `pace{tps: 0|2|10|40}` (0 = пауза), поведение RimWorld (§1.2).
- Буфер команд: `commands{batch}` копится и применяется ПАКЕТОМ на границе
  следующего тика, в порядке получения; каждая команда пишется в
  `runs/<session>/commands.jsonl` с тиком применения — фундамент GAME-DET (§1.3).
  На Этапе 0 команд-действий нет (реестр `WORLD_COMMANDS` пуст) — это крючок
  для нашёптываний Этапа 2.
- Выдача после каждого тика: полный `snapshot{tick, agents[], meta}` +
  `events{tick, items[]}` (новые события EventLog с прошлой выдачи, форма — как
  S7 JSONL-экспорт) (§1.4).
- Легальные сообщения: `pace`, `ping` (+ `commands`/`hello`) (§1.5).
- Сессия: `runs/<session>/` с `manifest.json` (seed, core_commit,
  protocol_version, grid, generated_at), `commands.jsonl`, `hashes.jsonl`.

`Agent` v1 в снапшоте: `{oid, x, y, body, deme, flags}`. **Важно про
координаты:** у ядра нет непрерывных x/y — агенты живут в целочисленных
клетках `(i, j)` решётки **5×5** (`ROWS, COLS` из `sim_eventlog`). Маппинг:
`x = j` (столбец), `y = i` (строка); `deme` = индекс клетки `i*COLS+j`
(со-локация = дема). `flags ⊂ {speaker, owner, bonded, demerzel}` из
мировых множеств ядра, ключ — oid.

**Клиент — `game/` (Godot 4.3+ .NET, GDScript):**

- `Net.gd` — `StreamPeerTCP`, handshake, кадрирование line-JSON, типизованные
  сигналы. Никакой игровой логики (§2.1).
- `Arena.gd` — тайловая карта 5×5, маркеры-кружки (цвет = роль из flags),
  интерполяция позиций между двумя последними снапшотами, `alpha` от Main,
  экстраполяции нет (§2.2). Косметический джиттер маркера — отдельный
  per-oid RNG, на клиент не влияет и в команды не уходит (§2.5).
- `Hud.gd` — Control-ноды: статус/тик/темп/поп, кнопки Pause/1x/4x/20x,
  минимальный инспектор пешки (§2.3, §2.4).
- `Main.gd` — оркестратор: fixed-timestep аккумулятор → `alpha`, хоткеи
  Space/1/2/3, роутинг клика к инспектору (id, body, дема, последние 5 событий
  агента из потока).

## Открытый вопрос для Стана (наблюдение, не баг)

При `seed=7` дефолтной конфигурации **полис естественно вымирает**:
pop 120 (t1) → ~90 (t500) → ~24 (t1500) → ~5 (t3000). Ядро — источник истины,
я его НЕ подкручивала. Для готовности Этапа 0 (агенты двигаются, тайм-контрол)
это не мешает — видно на первых сотнях тиков. Но смоук «10 мин на 20x»
(=12000 тиков) упрётся в почти пустой мир. Это вопрос уровня vision
(долгожительство «супер-RimWorld»), не каркаса. Смоук всё равно валиден:
он про стабильность интерполяции и утечки, не про численность.
