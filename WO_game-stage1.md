## Факты разведки (на них опирается скоуп — не выдумывать сверх)

**Геометрия (БАГ Этапа 0, чинить первым).** Субстрат `Polis→…→CommWorld`
живёт на решётке **14×14** (`sim_comm.py:55`, `w.soil/plant/T.shape`), но
`arena_side=6` запирает пешек в **6×6** (i,j ∈ 0..5). Сервер сейчас берёт
`ROWS,COLS` из `sim_eventlog` (**5×5**) → пешки на индексе 5 рендерятся за
сеткой, а `deme=i*5+j` алиасит. Настоящий грид арены = `arena_side` (или полный
`soil.shape`, если `arena_side is None`).

**Данные per-agent (keyed by oid), которые ЕСТЬ всегда:**
- `body` (масса, кг), `age` (тики), `gene` (тепловой оптимум K) — `Animal`.
- фаза жизни `Pawn.phase_of(age)` ∈ INFANT/MATURE/ELDER (`pawn.py:43`),
  пороги A_MAT=20/A_OLD=100/A_MAX=300.
- метаболизм тика `DebtLedger._metabolism(w,a)` (`debt.py:163`, read-only).
- смерть: `body<DEATH(0.05)` (голод) или (только Демерзель) `age≥A_MAX`.
- **belief** `w.belief[oid]` (строка-сводка «best food (i,j); know N»),
  **mem** `w.mem[oid]` (`{(i,j):(food,last_day)}`), **from_hearsay**
  `w.from_hearsay[oid]` (клетки, известные с чужих слов) — `sim_comm.py:160`.
- **personality** `w.pawn(oid).personality` — 5 осей (`personality.py:25`).
- флаги: `speaker` (`w.speaker`), `owner` (`w.owner_ids()`), `demerzel`
  (`w._demerzel_oid`) — есть в стоковом run.

**Данные, которые ВЫКЛЮЧЕНЫ по умолчанию** (пусты в стоковом seed=7):
- долг: `w._debt.stage[oid]`, `is_bonded`, `debt` edges — только при `debt_on`.
- publicgood: `w._pg.prop[oid]` — только при `pg_on`.
- dunbar-связи: `w._dunbar.known[oid]` — только при `dunbar_K`.
- extort/delegate-марки репутации — только при соответствующих тумблерах.
- артефакты/store/capital (богатство сверх body) — только при `artifacts/store_on`.
→ Чтобы долг/репутация были НАБЛЮДАЕМЫ, игровой конфиг должен эти модули
включить (см. развилку B). Иначе оверлеи честно показывают «модуль off».

**EventLog для хроник:** высокосигнальные виды (`actor`+`where`+`dm`+`data`):
`birth`(+parent — единственная линия родства), `death`, `communication`
(правда/ложь спикеров), `extort`, `delegate_remit`, `debt_default/pay/loan/
enforce`, `pg_punish`. Шумные (фильтровать): `cognition` (КАЖДАЯ пешка КАЖДЫЙ
тик), `move`, `forget`. Шаблоны нарратива уже есть в `EventLog.narrate`
(`sim_eventlog.py:218`). ⚠️ `boom/crash/local_extinction/recolonize` НЕ
эмитятся в `step` — их считают детекторы демо-раннеров; для хроник эпох их
надо гонять в обёртке (развилка C). ⚠️ часть debt-событий пишется только в
`w._debt.events`, не в EventLog.

## Гейты

- **GAME-OFF / GAME-DET / GAME-PROTO** — прежние, остаются зелёными
  (новые поля read-only; протокол аддитивен; включение модулей в игровом
  конфиге детерминизма не рушит — replay того же конфига идентичен).
- **GEOM** (новый): ни одна пешка не выпадает за репортнутый грид; `deme` без
  алиасинга (тест на seed+T).
- **CHRONICLE-FILTER** (новый): `cognition/move/forget` не попадают в ленту;
  объём ленты ≪ полного потока событий.
- Смоук вручную: инспектор живой пешки (needs+thoughts обновляются), ≥3 оверлея
  переключаются и совпадают с данными ядра, лента хроник читаема; 10 мин на 20x.

## Решения (Стан, 14.07) — зафиксированы

- **A. Инспектор — по запросу.** Дорогие данные (belief/personality/mem) идут
  ответом на `inspect{oid}`, не в каждом снапшоте. Снапшот остаётся лёгким.
- **B. Включить ВСЁ.** Игровой конфиг поднимает все observability-модули
  (debt/publicgood/dunbar/артефакты/store/capital/репутация-марки) на
  калиброванных параметрах — чтобы долг/богатство/репутация были наблюдаемы
  с первого тика. Пофиксить, если pop нестабилен (замер обязателен).
- **C. Хроники — событийные.** Лента строится из видов, эмитящихся в `step`.
  Эпохи (boom/crash/вымирание через детекторы) ОТЛОЖЕНЫ — отдельным витком.
- **D. Геометрия — задача 1.0 + принцип целостности.** Геометрия чинится
  первой (1.0); сверх того — каждая итерация оставляет клиент визуально
  целостным (смоук покадрово, не только в финале).

## Критерий готовности Этапа 1

Клик по пешке открывает карточку с её нуждами (голод/возраст/тепло/фаза) и
мыслями (во что верит, что помнит); ≥3 оверлея карты переключаются и совпадают
с данными ядра; лента хроник читаемо рассказывает историю полиса из EventLog;
появление/смерть агентов плавные. Скриншот + короткий гиф каждого нового UI —
в отчёт. Стоп.
