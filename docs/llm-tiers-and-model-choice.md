# Тиры разума и выбор модели

Сама архитектура слоя расщепляет «одну ллмку» на два тира — см. [Cognition - 9 principles](cognition-9-principles.md) (принцип 4). Вопрос не «какая модель», а «какие две и где».

## Двухтировая раскладка
- **Массовый / когортный тир — локально на SOW (RTX 3090, 24 ГБ).**
  - **Лид: Qwen3.6-35B-A3B** (MoE, 35B всего / 3B активных, Apache 2.0, нативный контекст 262K). По независимым тестам на 24 ГБ — одна из лучших практических open-weight для локального кода; MoE даёт коммерческую скорость без потери глубины; лучший decode на коротких контекстах (~65.6 t/s в llama.cpp), а с `--n-cpu-moe 12` влезает полный 64K контекст на 24 ГБ. Прямой наследник январского `Qwen3-30B-A3B`.
  - **Альтернатива (плотная, ради потолка качества): Gemma 4 31B** (Apache 2.0): ~86.4% на τ2-bench по агентному tool-use, но все 31B активны ⇒ медленнее на токен, чем MoE.
  - **Совсем тривиальные решения:** плотный кодер Qwen3.6-27B (~16 ГБ Q4).
  - **Не на одну 3090:** Kimi K2.6 (1T/32B), DeepSeek V4 Pro (744B/40B), GLM-5, Llama 4 Scout.
  - **Сервинг: vLLM, не Ollama.** Нужен continuous batching и — главное — **grammar/JSON-constrained декодинг** (грамматика физически не даёт выдать нелегальное действие). Мимо грабель с `keep_alive` в Ollama, особенно болезненных для loop-нагрузки.
- **Фокальный тир — Claude по API через WireGuard** (переиспользуем существующий путь саммаризации). Sonnet — дефолтный мозг фокальных; Opus — только для высокоставочных / изучения обмана-нарратива.

## Что НЕ изменилось с января
Критерии отбора: малая MoE либо плотная ~7–31B, сильная на constrained-JSON и следовании инструкциям, под grammar-декодингом. Сдвинулся только конкретный чекпоинт.

## Ортогональность воспроизводимости
Выбор модели **не влияет** на воспроизводимость: реплей `cognition`-лога ([Reversibility and replay](reversibility-and-replay.md)) реконструирует прогон даже для стохастической модели. Локальную можно гнать greedy/seed ради почти-детерминизма, но бит-стабильности через версии vLLM и батчинг это не даёт — гарантия именно лог.

## Секвенирование
Минимальный скелет (одна фокальная пешка) начинать с Claude по API — ноль возни с инфрой. Поднимать vLLM+Qwen на SOW — только на стадии когорт. Не строить serving-стек раньше, чем заработает петля.
