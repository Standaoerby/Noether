# Noether Game — архитектура связки и протокол v1

Статус: КОНТРАКТ. Дата: 2026-07-13. Автор: Гайка (по отчёту исследования
платформы и решениям Стана). Изменения протокола — только через PR с
обновлением этого файла и `protocol_version`.

## Принципы (нерушимые)

1. **Python-ядро — источник истины.** Детерминированные тики, EventLog,
   сохранение массы, канон `Code/sim_*.py` неприкосновенен. Клиент — только
   презентация и ввод.
2. **Развязка через протокол, не через репо.** Клиент (`game/`, Godot) и
   сервер (`stage3/gameserver.py`) живут в одном репо, но общаются ТОЛЬКО
   по этому контракту. Любая сторона может быть переписана без другой.
3. **Команды входят в мир только на границе тика.** Клиент буферизует,
   сервер применяет пакетом, детерминированно. (seed + командный лог) =
   бит-в-бит реплей — это и научные данные (как ведёт себя человек-бог),
   и регрессионный тест.
4. **Два RNG-мира.** Логика — seeded-потоки ядра (входят в fingerprint).
   Косметика — RNG клиента, пересеваемый от состояния на границе фазы;
   никогда не влияет на ядро. «Случайность замывается между фазами».
5. **Fixed timestep + интерполяция.** Ядро: tps ∈ {0, 2, 10, 40}. Клиент:
   рендер 60+ FPS, интерполяция между двумя последними снапшотами,
   экстраполяции нет.

## Транспорт

- TCP loopback `127.0.0.1:42017` (порт конфигурируем).
- Кадрирование: line-delimited JSON (один объект = одна строка `\n`).
- Дорожная карта сериализации: JSON (сейчас) → MessagePack (когда формат
  застынет) → protobuf (если потребуются строгие схемы). Переход = мажорная
  версия протокола.

## Версионирование

- `protocol_version` — целое; мажорные изменения ломают совместимость и
  требуют отказа на handshake. Добавление НЕОБЯЗАТЕЛЬНЫХ полей — минорно
  и версии не меняет; обе стороны обязаны игнорировать незнакомые поля.
- Поля никогда не переименовываются и не меняют тип; вместо удаления —
  депрекация (комментарий здесь).

## Сообщения v1

### Клиент → сервер
| type | поля | семантика |
|---|---|---|
| `hello` | `protocol_version:int, client:"godot", client_version:str` | первое сообщение; сервер отвечает `hello` или `error` |
| `pace` | `tps:int` (0/2/10/40) | темп; 0 = пауза |
| `commands` | `batch:[Command]` | буфер действий игрока; применение на границе тика |
| `ping` | `nonce:int` | здоровье канала |
| `inspect` | `oid:int` | запрос подробной карточки пешки (Этап 1, минорно); сервер отвечает `inspect_result` |

`Command` (v1, будет расти по этапам):
`{"cmd":"...", "target":oid|null, "payload":{...}, "client_ts":int}`
Этап 0: команд-действий нет (только pace/ping). Этап 2 добавит
`whisper_directive`, `whisper_text`, `force_intent` — здесь же, минорно.

### Сервер → клиент
| type | поля | семантика |
|---|---|---|
| `hello` | `protocol_version:int, core_commit:str, seed:int, session:str` | подтверждение; несовпадение мажора → `error` + закрытие |
| `snapshot` | `tick:int, agents:[Agent], meta:{...}` | состояние после тика (v1 — полный; дельты = минорное поле `base_tick` позже) |
| `events` | `tick:int, items:[Event]` | новые события EventLog с прошлой выдачи; Event — как в JSONL-экспорте (S7-поля включены) |
| `pong` | `nonce:int` | ответ на ping |
| `error` | `code:str, message:str` | внятная ошибка |
| `inspect_result` | `oid:int, alive:bool, cell, flags, needs, thoughts, personality, wealth, debt` | ответ на `inspect` (Этап 1, минорно); дорогие данные пешки по запросу, не в снапшоте |

`Agent` v1: `{"oid":int, "x":int, "y":int, "body":float, "deme":int,
"flags":["bonded","speaker",...]}` — расширяется минорно. **Этап 1 добавил
(минорно):** `age:int, phase:str(INFANT|MATURE|ELDER), therm:float (0=идеал,
комфорт=−|gene−T|), margin:float (body над порогом голода DEATH)`.

`inspect_result` (Этап 1): `needs:{body,margin,age,phase,therm,metabolism}`,
`thoughts:{belief:str, mem:[{cell,food,src:seen|heard}]}`,
`personality:{hunger_caution,deception_lean,attention_K,trust_gate,
stake_sensitivity}`, `wealth:{body,store,capital}` (store/capital=0, если слой
артефактов выключен), `debt:{on:bool[,stage,bonded,owed]}`. Дорогое (belief/
память/личность) отдаётся ТОЛЬКО по `inspect`, не в каждом снапшоте.

## Сессия и реплей

Сервер на старте создаёт `runs/<session>/`: `manifest.json` (S6-эмиттер:
seed, core_commit, protocol_version, generated_at), `commands.jsonl`
(каждая принятая команда с тиком применения). Реплей: тот же seed + прогон
commands.jsonl без клиента → идентичный `state_hash` (гейт GAME-DET).

## Будущие слои (не сейчас; фиксируются здесь при заряде этапов)

- Этап 1: инспектор-needs, оверлеи, хроники (только новые поля snapshot/events).
- Этап 2: нашёптывания. Свободный текст → АСИНХРОННЫЙ LLM-вызов вне тикового
  цикла → структурированный интент (constrained JSON) → буфер команд. Ядро
  решает легальность и эффект; LLM только переводит текст. Форсинг копит
  стресс/подозрительность → психоз/«ведьма» (модель в vision-доке).
- Этап 3: worldgen «точка высадки» (в ядре, seed→мир), климат-дрейф,
  Storyteller-слой поверх EventLog.
