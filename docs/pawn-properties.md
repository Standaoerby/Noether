# Свойства пешки — единый справочник

> Составлено Гайкой чтением исходников против `main` (`7373128`): `stage3/pawn.py`,
> `stage3/personality.py`, `stage3/polis.py`, `stage3/debt.py`, `Code/sim_world.py`.
> Не по памяти. При изменении модели — перечитать те же файлы и обновить.

## Ключевая рамка

**Пешки как одного толстого объекта не существует.** Свойства размазаны по трём слоям:

1. **Канон (Animal, mod A)** — шесть чисел в субстрате (`Code/sim_world.py`). Байт-неприкосновенно,
   сохраняет массу. Это ВСЁ, что есть в субстрате.
2. **Толстая пешка (`stage3/pawn.py` + `personality.py`)** — read-only обёртка над Animal по oid.
   Личность + производная фаза. Массу не трогает; только смещает слой решений Stage-3.
3. **Модульное per-oid состояние (`stage3/polis.py` и модули)** — словари, которые МИР держит поверх
   пешки: владение, дом, познание, долг, поток власти, репутация, роли. Включаются конфигом.

Смерть у обычной пешки одна: `body < DEATH` (канон). Возрастного отсева нет — пешка, что ест, бессмертна.

## Собранный вид

Метод `GameSession.inspect(oid)` (`stage3/gameserver.py`, ветка `feat/game-stage1`) складывает эти слои в
одну карточку: `needs` (body/margin/age/phase/therm/metabolism) · `thoughts` (belief/mem) · `personality`
· `wealth` (body/store/capital) · `debt`. Это «пешка целиком» одним вызовом — дорогие поля (belief/память/
личность) отдаются ТОЛЬКО по запросу, не в каждом снапшоте.

## Инварианты

- Личность (7–11) посеяна **детерминированно из oid** — прогон воспроизводим, не случаен между запусками.
- Канон (1–6) и производные (12–18) массу не трогают — дрейф материи < 1e-9.
- Модульные слои (19–38) включаются конфигом; при выключенном слое поле отсутствует/нулевое, а не ломается.
